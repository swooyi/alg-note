# 퀴즈 기능 기획

## 1. 개요

`퀴즈`는 실제 큐브 없이 앱만으로 케이스 이미지를 보고 대표 알고리즘을 떠올리는 리콜 기능이다.

- 시간 측정이나 기록을 목적으로 하지 않는다.
- 문제의 케이스 이미지를 보고 4개의 알고리즘 보기 중 정답을 선택한다.
- 기존 드릴과 동일하게 현재 선택된 케이스를 문제 출제 대상으로 사용한다.
- 기능 이름은 `퀴즈`로 한다.

## 2. 드릴과의 차이

| 구분 | 드릴 | 퀴즈 |
| --- | --- | --- |
| 주된 목적 | 실제 큐브를 사용한 연습 | 앱만 사용한 알고리즘 리콜 |
| 문제 제시 | 기존 드릴 방식 | 케이스 이미지 |
| 답변 방식 | 실제 수행 | 대표 `alg` 4지선다 |
| 시간 기록 | 사용 | 사용하지 않음 |

## 3. 진입 방식

- 기존 우측 하단 실행 영역에 `퀴즈`와 `드릴` 버튼을 세로로 배치한다.
- 현재 선택된 케이스가 하나도 없으면 `퀴즈` 버튼을 비활성화한다.
- 퀴즈는 현재 화면 위에 뜨는 플로팅 UI가 아니라 별도의 퀴즈 화면으로 전환한다.
- 퀴즈 화면 좌측 상단에는 드릴과 같은 뒤로가기 버튼을 둔다.
- 뒤로가기로 목록에 복귀해도 진행 상태를 저장한다.

예시:

```text
[ 퀴즈 ]
[ 드릴 ]
```

## 4. 퀴즈 모드

### 4.1 리캡

- 기본 선택 모드다.
- 선택된 케이스를 무작위로 섞어서 한 번씩 출제한다.
- 모든 문제에 답하면 퀴즈를 종료한다.
- 진행 상황을 `현재 문제 / 전체 문제` 형식으로 표시한다. 예: `3 / 20`
- 마지막 문제에 답하면 `다음 문제` 대신 `결과 보기` 버튼을 표시한다.

### 4.2 트레이닝

- 별도의 종료 시점 없이 문제를 계속 출제한다.
- 동일한 케이스가 바로 연속해서 나오지 않도록 한다.
- 선택된 케이스가 하나뿐이면 연속 출제 방지 규칙의 예외로 처리한다.
- 전체 문제 수가 없으므로 `12문제째`처럼 현재까지의 출제 수를 표시한다.

### 4.3 모드 전환

- 퀴즈 진행 중에도 리캡과 트레이닝을 전환할 수 있다.
- 모드를 전환하면 전환한 모드의 새 퀴즈를 시작한다.
- 리캡이 기본값이다.

## 5. 문제와 보기 구성

### 5.1 문제 출제 대상

- 문제는 사용자가 현재 선택한 케이스에서만 출제한다.
- 문제 순서는 퀴즈를 시작할 때 무작위로 섞는다.
- 각 문제에는 현재 카드 설정을 따르는 케이스 이미지를 표시한다.
- `3D / Top` 이미지 설정은 기존 카드의 설정을 그대로 사용한다.
- 답변 전에는 케이스 이름과 그룹명을 모두 숨긴다.

### 5.2 정답 보기

- 현재 문제 케이스의 대표 `alg`를 정답으로 사용한다.
- 보기에는 `setup`을 제외하고 `alg`만 표시한다.
- 복수 정답이나 대체 알고리즘 판정은 구현하지 않는다.
- 사용자가 보기 하나를 클릭하거나 터치하면 해당 답을 제출한다.

### 5.3 오답 보기

오답 보기는 현재 퀴즈의 출제 대상과 무관하게 전체 케이스 데이터에서 가져올 수 있다. 오답 후보는 현재 문제인 한 케이스만을 기준으로 결정한다.

후보 선택 우선순위는 다음과 같다.

1. 정답 케이스와 같은 `group`에서 후보를 찾는다.
2. 같은 `rec`을 가진 케이스를 우선한다.
3. 대표 `alg`의 시작 동작이 정답과 유사한 케이스를 우선한다.
4. 조건이 같으면 그룹 내 배치 순서가 정답 케이스와 가까운 케이스를 우선한다.
5. 후보가 부족하면 동일 `rec` 조건을 완화하고, 같은 그룹의 인접 케이스 등으로 보충한다.

알고리즘 시작 유사도는 문자열 글자 수가 아니라 공백으로 구분된 동작 토큰의 공통 접두부 길이로 비교한다. 예를 들어 시작 동작이 `R U R'`까지 같은 후보는 `R U2`까지만 같은 후보보다 우선한다.

- 정답 1개와 오답 3개로 총 4개의 보기를 만든다.
- 동일한 대표 `alg`가 보기에 중복되지 않도록 한다.
- 네 보기의 표시 순서는 문제마다 무작위로 섞는다.
- 보기는 데스크톱과 모바일 모두 세로로 배치한다.

## 6. 답변과 피드백

- 사용자가 보기를 선택하면 해당 문제의 답을 확정하고 모든 보기를 잠근다.
- 정답을 선택하면 맞음 표시를 보여준다.
- 오답을 선택하면 선택한 보기에 틀림 표시를 보여주고 올바른 보기에 정답 표시를 함께 보여준다.
- 답변 후 정답 케이스의 이름을 공개한다.
- 답변 후 `세부정보`와 `다음 문제` 버튼을 표시한다.
- `세부정보`는 기존 케이스 상세 모달을 재사용한다.
- 상세 모달의 기존 알고리즘 수정 기능도 그대로 허용한다.

## 7. 문제 이동

- 좌우 화살표로 문제 사이를 이동한다.
- 왼쪽 화살표로 이미 답한 이전 문제를 확인할 수 있다.
- 이전 문제로 돌아가도 선택한 답과 판정 결과를 유지한다.
- 답이 확정된 문제는 다시 선택하거나 수정할 수 없다.
- 아직 답하지 않은 다음 문제로 미리 이동할 수 없다.
- 답변 직후에는 `다음 문제` 버튼을 주 동작으로 사용한다.
- 이미 출제된 다음 문제가 있을 때만 오른쪽 화살표를 활성화한다.

## 8. 결과 화면

### 8.1 리캡 결과

- 마지막 문제에 답하면 `결과 보기` 버튼을 표시한다.
- 결과 화면에는 맞은 문제 수, 틀린 문제 수, 정답률을 표시한다.
- 틀린 케이스 목록을 표시한다.
- 틀린 케이스를 클릭하면 기존 케이스 상세 모달을 연다.

### 8.2 오답 다시 풀기

- 결과 화면에서 틀린 문제만 다시 풀 수 있다.
- 다시 풀기 문제는 새로운 순서로 출제한다.
- 다시 풀기에서도 틀린 문제만 재차 도전할 수 있다.
- 모든 오답을 맞힐 때까지 반복할 수 있다.
- 최초 결과와 다시 풀기 결과는 서로 구분해서 표시한다.

예시:

```text
최초 결과: 12 / 20
오답 다시 풀기: 6 / 8
```

### 8.3 기록 범위

- 완료된 퀴즈 결과를 누적 저장하거나 통계화하지 않는다.
- 장기 정답률, 최고 점수, 과거 기록 기능은 현재 범위에 포함하지 않는다.

## 9. 진행 상태 저장

- 리캡과 트레이닝 모두 진행 중인 상태를 저장한다.
- 목록으로 나가거나 앱을 새로고침한 뒤 다시 진입하면 `이어하기 / 새로 시작`을 표시한다.
- 이어하기에는 다음 상태가 유지되어야 한다.
  - 퀴즈 모드
  - 대상 케이스 구성
  - 출제 순서와 현재 위치
  - 각 문제에서 선택한 보기
  - 정답·오답 판정 결과
  - 오답 다시 풀기 상태
- `새로 시작`을 선택하면 기존 진행 상태를 대체한다.
- 현재 선택된 케이스 구성이 저장 당시와 달라졌다면 이어하기를 제공하지 않고 새 퀴즈를 시작한다.
- 퀴즈 진행 중 케이스나 대표 알고리즘을 수정해도 현재 세션 데이터는 즉시 바꾸지 않는다.
- 수정된 데이터는 퀴즈에 다음으로 진입할 때 반영한다.

## 10. 화면 구성 요약

```text
┌──────────────────────────────┐
│ ←        리캡       3 / 20  │
│                              │
│          케이스 이미지       │
│                              │
│ [ 알고리즘 보기 1 ]          │
│ [ 알고리즘 보기 2 ]          │
│ [ 알고리즘 보기 3 ]          │
│ [ 알고리즘 보기 4 ]          │
│                              │
│       ←             →        │
│                              │
│ 답변 후:                     │
│ [ 세부정보 ] [ 다음 문제 ]   │
└──────────────────────────────┘
```

- 상단에는 뒤로가기, 현재 모드, 진행 상황을 함께 표시한다.
- 답변 전에는 케이스 이름과 그룹명을 노출하지 않는다.
- 알고리즘 보기 4개는 화면 크기와 관계없이 세로로 배치한다.
- 모바일에서는 각 보기와 이동 버튼이 충분한 터치 영역을 가져야 한다.

## 11. 현재 구현 범위에서 제외

- 시간 측정 및 시간 기록
- 사용자가 알고리즘을 직접 입력하는 주관식 답변
- 복수 정답 또는 동치 알고리즘 판정
- 완료된 퀴즈의 누적 기록과 장기 통계
- 선택 케이스 변경 후 기존 세션 이어하기

## 12. 구현 시 확인할 사항

- 오답 후보의 `alg` 공통 접두부 비교는 알고리즘 동작 토큰 기준으로 수행한다.
- 동일한 보기 문자열이 중복되지 않는지 확인한다.
- 같은 그룹에서 오답 3개를 확보하지 못하는 데이터가 있는지 확인하고, 부족할 때 사용할 최종 후보 확장 범위를 구현 단계에서 결정한다.
- 모드 전환으로 현재 진행 상태가 대체되는 시점의 확인 UI 필요 여부를 구현 단계에서 결정한다.
- 저장된 세션과 현재 선택 케이스 구성이 같은지 안정적으로 비교할 식별자 구성을 정한다.
- 모바일 `390x844`에 가까운 화면에서 이미지, 4개 보기, 이동 버튼, 답변 후 버튼이 겹치거나 화면을 가리지 않는지 확인한다.

## 13. 완료 조건

- 선택된 케이스가 없으면 퀴즈를 시작할 수 없다.
- 선택된 케이스만 문제로 출제되고, 오답 보기는 전체 데이터에서 규칙에 따라 선택된다.
- 리캡은 각 문제를 한 번씩 출제한 후 결과 화면으로 이동할 수 있다.
- 트레이닝은 동일 케이스의 즉시 반복을 피하면서 계속 진행된다.
- 정답과 오답 피드백, 케이스 이름 공개, 상세 모달 진입이 정상 동작한다.
- 이전 문제의 답변 상태가 유지되고 미출제 문제로 미리 이동할 수 없다.
- 나갔다가 다시 진입했을 때 이어하기와 새로 시작이 정상 동작한다.
- 오답만 반복해서 다시 풀 수 있다.
- 데스크톱과 모바일에서 4개의 알고리즘 보기가 세로로 정상 표시된다.
